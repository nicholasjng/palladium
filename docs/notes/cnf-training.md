# Continuous normalizing flow: first end-to-end workload

2026-09-19. Implemented in `palladium.cnf_training`, with a runnable
`examples/08_cnf_density.py` and `benchmarks/bench_cnf_training.py`.

## Model and numerical contract

The first model is an unconditional 2D density with a standard Gaussian base.
A time-dependent, single-hidden-layer tanh MLP supplies the velocity field.
Width 4 gives 26 trainable weights and biases. The parameters include time as
an input but no external conditioning variable yet.

For each hidden unit h = tanh(wx*x + wy*y + wt*t + b), the two output weights
are ux and uy. Its exact contribution to divergence is
(ux*wx + uy*wy)*(1-h*h). We integrate (x, y, delta_logp) with
d(delta_logp)/dt = -divergence. Density evaluation integrates from data at
t=1 to base at t=0, giving logp(data) = logp_base(z0) - delta_logp_reverse.
The same flow supports generation in the other direction via
`make_flow(..., reverse=False, variant="forward")`.

One Pallas forward kernel performs all fixed RK4 steps, evaluates the MLP,
and stores sparse checkpoints. One backward kernel recomputes within each
checkpoint interval and applies the discrete RK4 transpose. Crucially, the
transpose is generated by `jax.vjp` of the pure RK4 step during Pallas tracing;
the MLP weight derivatives are not hand-written. Differentiating the exact
divergence includes the mixed state/parameter derivatives required for CNF
likelihood training. The emitted arithmetic needs `add_any` for cotangent
accumulation, now supported for Palladium's numeric types.

The pure-JAX baseline uses vectorized hidden-unit operations and a batched
RK4 loop. It is independent of the scalar Pallas step implementation.
Available variants are pure JAX, fused forward with a reference VJP, and
fused forward plus checkpointed reverse VJP. Interval 1 is full history.
Loss reduction and Adam remain regular JAX operations in the same compiled
optimizer step.

These are derivatives of the finite-step augmented solver. The integrated
continuous divergence approximates the log determinant of the finite-step
map; it is not an exact discrete change-of-variables identity at arbitrary
step sizes. We test both a Jacobian/log-determinant comparison and refinement
of the trained model's timestep.

## Correctness and learning

Tests check exact divergence against an automatically differentiated trace,
its weight derivatives, every input/weight cotangent against CPU JAX, full
history versus sparse intervals (including partial segments), translation
density, forward/reverse consistency, and the inverse-map Jacobian.

The default learning task fits an equal mixture of Gaussians centered at
(-1.3,-0.4) and (1.3,0.4), with standard deviations (0.45,0.65).
Training and held-out data use separate deterministic seeds. With 256 points,
width 4, 16 RK4 steps, interval 4, and 500 Adam updates:

- Held-out NLL: 3.32332 initially, 2.30719 after training.
- Known target NLL on those held-out points: 2.26538.
- CPU reference agrees with the trained MPS model.
- Doubling to 32 RK4 steps agrees at the reported float32 mean NLL precision.
- The final 500-update run took 0.344 s, excluding the first training call
  (171.1 ms including tracing and compilation, with warm Metal caches). It synchronizes at progress
  checkpoints and completion, so this is not the per-step latency benchmark.
  Metrics, training progress, and final weights are saved in
  [`cnf-training-fit.json`](cnf-training-fit.json).

The automated recovery gate requires a held-out improvement of at least
0.7 nats, NLL within 0.2 nats of the known target on the same held-out set,
CPU agreement, small refinement error, and trained-weight gradient agreement.
The finite held-out NLL gap is not an exact KL estimate or a generalization
claim beyond this small synthetic example.

## Complete-step benchmark

JAX 0.11.1, 256 points, width 4, 16 steps. Fifteen warmed samples start from
identical optimizer states. Variant order rotates, every sample synchronizes,
and input transfers are excluded. Persistent compilation caches were not
cleared; first execution may include lazy Metal compilation.

| Variant | Median update (ms) | Min–max (ms) | Checkpoints (KiB) | Compile / first execute (ms) |
|---|---:|---:|---:|---:|
| Vectorized JAX, CPU | 1.392 | 1.295–1.728 | — | 326.3 / 2.9 |
| Vectorized JAX, MPS | 17.609 | 15.125–20.309 | — | 112.5 / 73.5 |
| MPS forward + reference VJP | 18.303 | 16.611–19.147 | — | 101.4 / 37.5 |
| Fused reverse, interval 1 | 0.509 | 0.429–0.656 | 48 | 107.5 / 3.6 |
| Fused reverse, interval 4 | 0.504 | 0.423–1.163 | 12 | 95.0 / 3.9 |
| Fused reverse, interval 8 | 0.529 | 0.449–1.378 | 6 | 93.1 / 4.0 |

Interval 4 gives about 35x lower median latency than vectorized JAX on MPS
and 2.8x lower than CPU JAX in this run. This is a tiny MLP, not a prediction
for large neural vector fields. Raw samples are in
[`cnf-training-timings.json`](cnf-training-timings.json).

Checkpoint bytes exclude weights, per-example parameter cotangents, and
other temporary storage. Shared weights are broadcast to per-example buffers
at the custom-call boundary; JAX reduces their cotangents back to shared
weights. The current interface therefore has O(batch * parameters) storage.
Prefix recomputation costs O(steps * interval); there is no local segment
tape yet. Higher-order differentiation of the MPS custom call itself is
unsupported, even though the first likelihood gradient differentiates the
divergence correctly. MPS currently compiles in FAST math mode.

## Reproduce and extend

From the modified jax-mps checkout, with Palladium installed:

```sh
JAX_PLATFORMS=mps,cpu env -u VIRTUAL_ENV uv run python ../palladium/examples/08_cnf_density.py
JAX_PLATFORMS=mps,cpu env -u VIRTUAL_ENV uv run python ../palladium/benchmarks/bench_cnf_training.py
JAX_PLATFORMS=mps,cpu env -u VIRTUAL_ENV uv run pytest -q ../palladium/tests/test_29_cnf_training.py
```

The CLI exposes batch size, hidden width, RK4 steps, checkpoint interval,
iterations, learning rate, device, and solver variant. It emits JSON with
training progress, held-out metrics, refined CPU evaluation, and trained
weights. Next application decisions are external conditioning and a real
low-dimensional dataset; larger hidden layers and stochastic divergence
estimation require separate correctness and performance work.
